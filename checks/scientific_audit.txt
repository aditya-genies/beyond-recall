Independent scientific and implementation audit — standalone study

Disposition
===========
PASS for the declared finite mechanism study. No source/result inconsistency was found in the frozen implementation or archived primary campaign. This is freshly authored standalone code using standard-library Python and synthetic SQLite state. It is not described as a formal clean-room process, a production-system evaluation, a new exactly-once theorem, or evidence of real-model recall quality. The tested mechanism interaction is concrete and inspectable; its general principles have public prior art.

Metrics and what they do not prove
=================================
The terminal conjunction is exact fixture fact-set equality, expected physical row cardinality, and final worker acknowledgement. Content equality collapses identical stored duplicates. Cardinality does not establish provenance, isolation or semantic truth. All final main acknowledgements are true, so that conjunct has no differential effect in the reported primary outcomes. Interim unsuccessful attempts remain visible in traces.

Decision continuity hashes all chosen/loaded decisions for the one declared logical intent in each case. It is a direct observed one-intent replay property, not a multi-job scheduling invariant. The script's alternate tape deliberately changes one fact; it measures response to an adversarial changed decision, not the frequency of stochastic LLM drift. No LLM, semantic retrieval, natural-language QA, external queue or remote vector service is evaluated.

Committed-effect calls means committed participant put/delete operations in the effect ledger. It excludes fixture setup, reset deletion, cleanup SQL and the separate intervening-write boundary operation. A repeated delete of an already absent row is still an operation. Repeated idempotent calls must not be relabeled duplicate stored rows. The saved-plan and receipt stores have identical plan retention wherever P is enabled; receipt comparisons do not gain an artificial advantage by deleting the no-receipt plan.

Verified factorial results
==========================
Terminal passes out of 66 structural cases:
D0P0R0: 29; D0P0R1: 41; D0P1R0: 37; D0P1R1: 49;
D1P0R0: 42; D1P0R1: 50; D1P1R0: 66; D1P1R1: 66.

checks/derive_factors.py derives all twelve conditional factor contrasts, each using the same 66 matched profile/history cells and identical first decisions, fault schedules and decision tapes. Its 792 pair comparisons are reused comparisons of the same 528 cases, not 792 additional experiments. There are no significance tests or population confidence intervals.

The main interaction is important: D1P1R0 and D1P1R1 both pass all 66 terminal cases, with 66 planning invocations each. Adding a receipt reduces participant committed operations from 317 to 275 (42 fewer). Thus a receipt is useful without being necessary for this selected final-state invariant under retained plans and deterministic addresses. The paper must not claim that all three mechanisms are universally necessary.

Address determinism improves cardinality without changing the content score or reducing operation counts in the paired cells. Retaining the decision improves content/continuity and reduces replanning but does not eliminate duplicate stored insertions when fresh addresses remain enabled. Receipt effects depend on the other settings. Those are isolated implementation contrasts within this finite model; they do not establish universal component necessity across other effect contracts, retention policies or providers.

Controls and retained negative boundaries
========================================
The source controls are discriminating. The planner reduces selected chronological facts to the latest value for each attribute. Removing the boundary predicate admits a future fact and changes the chosen result; removing the enabled predicate admits a later retracted fact and changes the result. The focused tests verify both counterfactual controls without modifying the frozen source. All variants use the same actual source/generation logic; these controls are not separate treatments in the D/P/R factorial.

The five boundary probes preserve limits rather than hiding them:
- Removing only the receipt leaves the retained decision and yields correct state after replay, with more calls.
- Removing only the decision leaves the receipt and suppresses replanning.
- Removing both permits a changed plan and changes final content despite correct cardinality.
- Abrupt exit before the decision is stored loses the unpersisted decision. This is outside the prepared-decision guarantee and is not counted as a main-regression failure.
- A resumed retained decision overwrites a newer intervening external value. The selected terminal fixture score can pass while that external write is lost. Therefore stable IDs and saved plans do not establish concurrency isolation or preservation of newer writers.

No coordination lease, concurrent-worker protocol, multiple-intent ordering, reclamation timer, native-framework comparison or arbitrary-generation advancement is claimed by this standalone model. It is a single-intent, specified-generation experiment. The reset checks demonstrate selected cancellation/cleanup histories, not transient-read consistency or atomic reset across stores.

Scientific interpretation
=========================
This is a reproducible finite mechanism/contract study with meaningful factorial interactions and genuinely abrupt subprocess recovery. It supports exact statements about its selected state, decision and call-count properties. Its principles have close prior work in RPC uncertainty, completion records, logged replay, idempotency and agent side-effect conformance. New code and more crash points alone do not establish a new recovery theory. A paper should emphasize the explicit invariant differences, the receipt redundancy interaction, and the retained negative boundaries, without promising selective-venue acceptance or production reliability.

No new scientific experiment was added by this audit. All factorial and reproduction summaries are read-only analysis of already recorded runs. No participant source, frozen specification, raw case or database was changed.
