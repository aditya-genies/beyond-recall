# Pinned MemTX snapshot-contract probes

This is a prospectively frozen, targeted verification protocol, motivated by source inspection. It is not a preregistered benchmark or an estimate of population reliability. The external baseline is the public `lxy1134/MEMTX_` repository at commit `4e1124ccd5fd384857463020e3497aa73ec93be6`. Its implementation stays in an external cache; this directory contains only our original calling adapter, checker, protocol and observations. No baseline code is patched, subclassed, or copied into this repository.

The contract being examined is arXiv:2607.23929v2: section 3.2 describes start-time visible records and rejection of a conflicting rival committed after the snapshot before authority comparison; section 3.6 describes reads under that transaction snapshot. Lifecycle visibility levels and snapshot membership are separate observations. Partial per-record commits are intentional and are not a target of these probes. Neither action-gate invariants nor predicate-level serializability is being tested.

## Read family: eight cases

For each of low, medium, high and external_action risk, and each of empty or one-unrelated-anchor initial state: open transaction A; read A; open B; stage and commit a synthetic fact in B; read the still-open A again; then open C after B's commit and read C. The anchor is action_safe so it is visible at every tested tier. B uses the same tier so its committed fact is visible at that tier. Query/top_k (100), requester permissions, purpose and values are fixed, with no live model or retrieval embedding. Compare post-commit A reads against A's captured IDs and distinguish them from C's fresh snapshot. A has no staged write, so read-your-writes is not a confound.

## Write family: sixteen cases

Cross empty/nonempty initial snapshot, old/fresh A start order, and four source-authority relations: equal authority/same source, higher A authority, lower A authority, and equal authority/different sources. All use low risk, adequate confidence 1.0, identical entity/attribute/scope, and the same overlapping validity interval (2026-01-01 through 2030-01-01), with logical now 2026-10-29. The single-valued synthetic room door_state is closed in A's observation and open in B's later observation. These explicit alternatives, not natural-language synonyms, define the contradiction.

In old-A cases, A opens and stages closed before B opens, stages open, and commits. Only then does A commit. Record transaction start times and actual staged-record creation times, as well as the declared observation times. In fresh-A controls, B commits first, then A opens and stages the candidate: source-authority correction is intentionally permitted by the stated policy and must not be labelled a temporal defect. The nonempty anchor is unrelated to the target slot and is identical between paired cases. Record A/B begin snapshots, stage outputs, complete commit return values, retrievals and complete store states. Report final-state consequences separately from conflict reasons. Do not force a preselected discrepancy count.

## Execution, provenance and falsification

Before any baseline execution, freeze this protocol, original adapter/checker source, full pinned source hashes, paper hash, external archive identity, and installed package versions. The full source archive is first verified against all tracked Git blob hashes to avoid treating a selected-file cache as a broken installation. Run the authors' exact `python -m pytest tests -q` command in a fresh environment installed from their requirements. If collection fails due to the absent optional tau2 tree, retain that full failure and execute all other original tests by an explicitly reported `--ignore=tests/test_tau2_adapter.py` follow-up; do not silently turn the collection error into a skip or a passing full suite. Raw upstream test logs remain external; publishable summaries preserve all counts, test IDs, failure/skip reasons, command lines and package versions without vendoring implementation excerpts.

Run all 24 synthetic API probes without filtering. A separate checker imports no MemTX or adapter code: it validates trace structure, fixture consistency, captured membership, commit states and classifications directly from recorded observations. A passing checker means evidence consistency, not satisfaction of the snapshot contract. Preserve outcomes that falsify either hypothesis. The latest-read behavior could be intended by the API despite the paper wording; label the finding a bounded paper/code discrepancy unless intent is clarified. Authority-based overwrite is only a discrepancy in the old-A/out-of-snapshot case, not in the fresh snapshot control.

No original primary data, previous extension results, manuscript, repository visibility or remote state is changed.
