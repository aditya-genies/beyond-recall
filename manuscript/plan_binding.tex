\subsection{Plan compaction and positional identity}
\label{sec:binding}
After examining the recorded outputs, we froze an exploratory integration protocol: 12 original-repeat-0/partial-repeat plan pairs, each replayed in three SQLite arms. All arms start from the exact archived partial snapshot with a common bijective public-ID/physical-address binding. The arms use (i) the recorded partial plan with stable intent/slot addresses, (ii) that same plan with fresh insertion addresses, or (iii) the retained original plan with its original stable addresses. Named targets are held fixed.

Two positional-replan integrations overwrite a completed prefix record with a different fact key; the other ten preserve the prefix. Fresh-address and retained-plan controls preserve it in all 12 pairs each. Both overwrites are the two partial responses of the same preferences scenario, the only scenario with a targetless first operation. They are not two independently sampled failure types or an estimated model failure rate.

The witness requires no contradictory model choice. Original slot 0 stores \texttt{reply\_style}; the partial snapshot already contains it. The model omits that completed fact and begins its remaining plan with \texttt{preferred\_units}. The adapter derives the same physical slot-0 address and overwrites the style record. Giving the identical remaining plan fresh addresses prevents that overwrite; retaining the original ordered plan preserves the original identity-to-operation binding. All 36 integrations, their before/after audit rows, and three focused control tests are retained. No additional model requests or semantic-synonym grading are involved.

This is an adapter contract failure, not evidence of a LangGraph defect or unsafe idempotency keys in general. LangGraph already warns that changing task/interrupt order can mismatch cached values \cite{langchainGraphAPI}. Featonby describes retaining original parameters and rejecting changed intent under the same request identifier \cite{featonbyIdempotentAPIs}; our positional upsert has no such rejection. The concrete model-output witness illustrates that known identity/order hazard when a memory planner compacts a plan by omitting an already represented fact. Stable logical-operation identities or mismatch rejection are additional controls, not evaluated remedies here.
