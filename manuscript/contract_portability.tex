\section{Public Contract and Backend Boundaries}
\label{sec:portability}
The following extensions test different contracts; their cells are not pooled with the admission experiment or primary factorial. They check bounded public behavior rather than certify an industry standard.

\subsection{MemTX snapshot descriptions and public implementation}
MemTX's v2 paper describes start-time visible-record snapshots, snapshot reads, and rejection of same-slot rivals committed after a transaction's snapshot before authority comparison \cite{li2026memtx}. We inspect the unmodified public \texttt{MemTXManager} at commit \texttt{4e1124cc}, the implementation registered as \texttt{memtx} in its experiment configuration \cite{memtx2026code}. Before execution, the protocol pins all 1,255 tracked upstream blobs, our adapter/checker, and the environment. The 24 traces comprise eight read probes, eight old-writer probes and eight fresh-writer controls; positive read controls are included within the read traces.

In all eight read probes, A begins before B commits and has no staged writes, yet A's open transaction retrieves B's later record, absent from A's captured snapshot. The probes span four risk tiers and initially empty or unrelated-anchor states. A fresh transaction after B includes and retrieves B as expected. Source inspection shows that retrieval filters the current store without filtering to the captured transaction IDs. This behavior is compatible with a latest-readable-state API; it differs from the separately described start-time read contract.

For old-writer probes, A stages an older observation of a single-valued synthetic door state; B commits a contradictory later observation before A commits. With an unrelated anchor making A's initial snapshot nonempty, all four source/authority variants reject A by the temporal rule. With an empty initial snapshot, equal-authority/same-source and higher-A-authority variants instead commit A and supersede B: two overwrites among eight old-writer cases. The other two empty cases reject by ordinary authority or review rules. The source's stale-rival check is guarded by snapshot nonemptiness. Eight controls in which A actually begins after B capture B and exercise intended authority-policy outcomes.

These are bounded paper/code conformance discrepancies. Clarification by the original authors could determine whether they are implementation or documentation defects. They do not refute MemTX's separately stated action-gating and cascading-repair invariants, evaluate model quality, or introduce a new snapshot-isolation principle. No public-source patch is made. The full original test invocation encounters a missing optional \texttt{tau2} collection dependency; after excluding only that adapter and installing missing public dependencies, all 94 unchanged non-\texttt{tau2} tests pass. The failed full invocation and intermediate dependency errors remain reported; the full suite is not labelled passing. The repository supplies our traces, protocol and file hashes; the upstream implementation, whose pinned repository has no license file, is fetched separately.

\subsection{Effect/receipt grouping across SQLite and Redis}
A separate extension implements four authored contracts on SQLite 3.51.2 and Redis 7.2.17: split effect/receipt commits; a grouped prepared-new-write path; in-primitive receipt/type preflight with grouped writes; and a single application key/row envelope. All profiles share a durable caller-side binding of operation identity to literal body, target version and authority epoch. All recheck version and epoch at the effect. These shared protections are not credited to backend primitives. The four profiles bundle different validation placement and storage boundaries; they are not a one-factor ablation or best possible vendor implementations.

Thirteen histories across four profiles and two backends declare 104 cells. Ninety-six execute, while eight remain explicitly inapplicable because the tested fault boundary does not exist in that profile. The campaign uses 154 fresh request processes and ten actual client exits at declared barriers. A real receipt-storage failure after caller entry inspection leaves an effect without a receipt in the grouped Redis Lua path; explicit SQLite rollback removes its preceding effect. In-primitive preflight prevents this particular fault in both backends. This illustrates documented differences between isolated script execution and rollback semantics \cite{redis2026eval,redis2026transactions,sqlite2026transactions}, not a Redis defect. A script that reads the invalid receipt hash before writing would already detect that fault. A separate valid-schema SQLite trigger error also demonstrates that preflight cannot predict every later failure.

All 96 executed cells have zero duplicate effects and zero stale-epoch effects. After revoke, eight receipt-hit retries acknowledge historical success while current visibility remains false at the new epoch; revocation holds target version fixed, so epoch checks remain discriminating. A split-path exit after effect commit but before receipt commit yields a stale-version conflict on literal retry, without silently rebasing. Explicit receipt garbage collection removes acknowledgement evidence by design in every profile; it is not an incidental failure rate. Historical success, current authority, and current visibility therefore require separate observations.

The checker reads all 48 final SQLite files and independently reduces Redis's native append-only stream from an empty base to all 72 final keys, checking each mutation and sixteen native multi-write groups. A separate graceful Redis restart preserves these keys. Twenty-one focused tests include twelve forged-evidence rejection checks. The dedicated study server, public image digest, version pins, commands and data are retained. No existing company service is accessed. Graceful restart is not server power loss; neither native grouping nor these bounded races prove arbitrary distributed durability or whole-plan atomicity.
